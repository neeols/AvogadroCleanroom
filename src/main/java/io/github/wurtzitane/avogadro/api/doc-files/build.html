Avogadro guide · Minecraft 1.12.2 / Cleanroom

Build and integrate Avogadro

Use the included Gradle wrapper and matching mapped artifacts. The documentation itself is generated by the JDK’s standard Javadoc doclet.

Common commands

.\gradlew.bat build
.\gradlew.bat javadoc
.\gradlew.bat javadocJar
.\gradlew.bat spotlessApply
.\gradlew.bat check

On macOS/Linux use ./gradlew. The distributable, source JAR, and Javadoc JAR are in build/libs; -mcp.jar is a development artifact. Open build/docs/javadoc/index.html for the site. Javadoc checks use strict syntax/link validation; check also validates internal Javadoc and formatting.

How documentation styling works

The standard JDK tool generates all reference pages, signatures, search, navigation, and tutorial pages. Gradle passes the authored CSS and JavaScript with native --add-stylesheet and --add-script options. Running javadoc copies and links those files automatically. No HTML replacement step, external web framework, hosted font, or CDN is needed. Guides remain readable without JavaScript; language switching, copy buttons, and the local contents list enhance them.

Compile a host mod

dependencies {
    compileOnly files('libs/avogadro-1.12.2-1.0.0-mcp.jar')
}

Use this inside an existing CleanroomGradle host project. This repository does not publish a Maven coordinate; do not invent one. Install matching distributable Avogadro and ModularUI JARs at runtime. Pass your host release through its normal Cleanroom reobfuscation. Declare required-after:avogadro if your integration requires Avogadro.

Development game and server

./gradlew runClient
./gradlew runServer

These use isolated development run directories and place the runtime JARs in their mods folders. The server requires its usual first-launch Minecraft EULA acceptance. Keep optional integrations safe when absent, and keep client-only rendering/export classes out of dedicated-server entry points.
