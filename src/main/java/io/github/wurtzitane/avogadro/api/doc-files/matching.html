public static MoleculeSpec pureWater() {
    // Extra NBT keys in a stack are allowed. Grade must be the string "pure".
    return AvogadroApi.builder("guide:pure_water").name("Purified water").smiles("O")
            .items("minecraft:potion@0#{Potion:\"minecraft:water\"}")
            .fluids("water#{Grade:\"pure\"}").matchContainers(true).build();
}

Tip NBT values have types. A numeric Grade:1 does not satisfy the string Grade:"pure". No tag means a qualified selector fails. Empty stacks do not match. Association methods such as items(...) replace their previous field, so pass all alternatives together.

Keep the full FluidStack

public static MoleculeSpec taggedFluid(Fluid water) {
    var stack = new FluidStack(water, 1000);
    stack.tag = new NBTTagCompound();
    stack.tag.setString("Grade", "pure");
    // The builder keeps the tag requirement. Amount is not a selector condition.
    return AvogadroApi.builder("guide:pure_water").smiles("O").fluids(stack).build();
}

Fluid amounts do not affect matching except that an empty stack fails. Container lookups pass through the contained stack and its tags. A bare Fluid query uses unqualified rules only.

Know which match wins

Know which match wins
PriorityItem lookupFluidStack lookup
1Generated molecule item’s saved IDMatching NBT-qualified fluid rule
2NBT selector: exact metadata before wildcard; more-specific NBT before later registrationDirect unqualified fluid ID
3Exact metadata, then registry-wide itemAvogadro fluid tag
4Avogadro item tag (earlier tag binding wins)Supported GregTech material binding/path
5Contained fluid, when permittedFluid-path fallback
6Supported GregTech material binding/path—
7Molecule-path fallback—

For fluid NBT ties, more required content wins, then later registration. Direct duplicate bindings and duplicate path fallbacks prefer later definitions. A matching qualified selector wins before a general selector. example:acetone may be a path fallback for other:acetone, so use explicit associations when ambiguity matters.

Group associations with tags

Java · method inside your host class; imports and full files below.

public static MoleculeBatch tags() {
    return new MoleculeBatch()
            .itemTag("guide:water_containers", false, "minecraft:water_bucket")
            .fluidTag("guide:water", false, "water")
            .register(AvogadroApi.builder("guide:tagged_water").smiles("O")
                    .itemTags("guide:water_containers").fluidTags("guide:water"));
}

Groovy · same API; place methods in your script or client helper as described.

mods.avogadro.molecules.itemTag('guide:water_containers', false, ['minecraft:water_bucket'])
mods.avogadro.molecules.register('guide:tagged_water', [smiles:'O', item_tags:['guide:water_containers']])

JSON · one definition per file unless a different destination is shown.

{
  "replace": false,
  "values": [
    "minecraft:water_bucket",
    "#guide:other_water_containers"
  ]
}

The JSON above is a tag file, saved as config/avogadro/server/data/guide/tags/items/water_containers.json. A molecule binds it with "item_tags":["guide:water_containers"]. Fluid tags use tags/fluids and fluid_tags. These are Avogadro dictionaries, not modern Minecraft datapacks or Forge ore-dictionary names.

Optional GregTech material binding

{"smiles":"Cc1ccccc1","materials":["gregtech:toluene"]}

The legacy adapter targets GregTechCEu 1.12.2 2.8.10-beta. gtceu:toluene is an alias; this does not imply compatibility with GTCEu Modern or every GregTech fork. Without the integration, ordinary item/fluid matching still works. No material is created.
